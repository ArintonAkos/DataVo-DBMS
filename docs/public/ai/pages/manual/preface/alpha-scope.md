# Release Scope & Boundaries

> Source route: /manual/preface/alpha-scope
> Source file: manual/preface/alpha-scope.md

This page states the contract: what DataVo is built to do, the settings under which its guarantees hold, and what it deliberately does not do. It applies to the v0.4 line published as **0.4.0-rc.1** (17 November 2026); see the [Roadmap](/manual/preface/roadmap) for the milestone breakdown and [Project Status & Stability](/manual/preface/project-status) for the state of each subsystem.

## The supported shape

One .NET 10 process opens a database directory (or an in-memory database), executes SQL or compiled LINQ through `DataVoContext`, ADO.NET, or the EF Core bridge, and closes it.

```csharp
using DataVo.Core;
using DataVo.Core.StorageEngine.Config;

using var db = new DataVoContext(new DataVoConfig
{
    StorageMode = StorageMode.Lsm,
    DiskStoragePath = "./app_data",
    LsmStrictFsync = true
});

db.Execute("CREATE DATABASE App");
db.Execute("USE App");
db.Execute("CREATE TABLE Events (Id INT PRIMARY KEY, Name VARCHAR(80))");
db.Execute("INSERT INTO Events (Id, Name) VALUES (1, 'created')");
```

Within that shape:

- **Durability.** With `StorageMode.Lsm` and `LsmStrictFsync = true` (the default), a commit is acknowledged only after its commit-log record has been flushed to stable storage, so an acknowledged write survives a crash or power loss, provided the drive honours flushes. With `LsmStrictFsync = false` the record is handed to the operating system and the acknowledgement does not wait: a process crash loses nothing the OS has accepted, but a power failure or kernel crash can lose the most recent commits. [WAL And Durability](/manual/storage-engine/wal-and-durability) has the details.
- **Isolation.** Explicit transactions (`BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK`) buffer their writes until commit, readers see MVCC snapshots, and updates and deletes revalidate rows before modifying them. Serializability across arbitrary multi-row predicates is not provided: a transaction that reads "all active users" can miss a row another transaction inserts. See [Transactions and MVCC](/manual/storage-engine/transactions-acid-mvcc).
- **Query results.** Every typed fast path returns exactly the result of the general SQL evaluator, or declines. Vector search with `FLAT` is exact; `HNSW` is approximate unless the planner routes the query to an exact scan, and its recall depends on the data. The SQL dialect is DataVo's own; the [SQL compatibility matrix](/manual/sql-language/sql-compatibility) lists what it accepts.
- **Native AOT.** `DataVo.Core`, `DataVo.Data` and code generated by `DataVo.Generators` publish with `PublishAot=true` without trim or AOT warnings. `DataVo.EntityFrameworkCore` is not covered, because EF Core itself is not.

## Boundaries

| Area | Status | What that means |
| --- | --- | --- |
| Multiple processes on one database directory | Not supported | `datavo.lock` rejects a second process. Contexts in one process share one engine. |
| Serializable isolation, phantom prevention | Not supported | No predicate or range locks. |
| Network access, PostgreSQL wire protocol | Not supported | Embedded only. A `DataVo.Server` bridge is planned but unscheduled. |
| Stored procedures, triggers, user-defined functions | Not supported | Keep that logic in application code. |
| Replication, high availability | Out of scope | |
| EF Core migrations, shadow properties, complex LINQ joins | Not supported | The EF integration is a bridge, not a provider. |
| `StorageMode.Disk` | Legacy | Readable for existing data; receives no durability or performance work. Use `Lsm`. |
| Long-term on-disk format guarantee | Not yet | Keep seed data or an export path until a stable release states one. |
| Browser / WebAssembly (`DataVo.Browser`) | Playground only | Powers this site's playground; not production-ready and not on npm. |
| Unity | Evaluation target | Narrow Editor and macOS IL2CPP smoke only; see [Unity evaluation status](/manual/preface/project-status#unity-evaluation-status). |

## SQL DATE contract

SQL `DATE` materializes as `DataVo.Core.DataVoDate` in the row APIs. `CellValue.AsDate()` and compiled `GetDate` return `DataVoDate`; on modern .NET, `FromDateOnly`, `ToDateOnly`, `AsDateOnly` and `GetDateOnly` convert explicitly to and from `System.DateOnly`. Persisted `DATE` bytes are unchanged by this API.
